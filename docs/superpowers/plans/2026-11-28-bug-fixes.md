## Saturday: wrong or lost content

### 1. The sanitizer deletes real job requirements (Reproduced)

- [ ] **Where:** `backend/security/sanitizer.py:20-21`
- **Cause:** any line matching `new (role|instructions|task)` or an unanchored `system:`
  is removed.
- **Example:** `Operating system: Linux required.`,
  `In this new role you will need ROS 2, C++ and French C1.` and
  `You will lead a new task force.` all become an empty string.
- **Effect:** adapters sanitize descriptions before storing them, so skills are lost before
  scoring. Stored rows stay wrong until fetched again.
- **Fix:** keep the line and flag it; the `<untrusted_data>` wrappers already mark postings
  as data. Keep removing control characters.
- **Also check:** whether `display:none` text and zero-width characters survive. Remove
  those instead of visible text.
- **Test:** the three lines above survive in `tests/test_sanitizer.py`.

### 2. `%` in a CV edit cuts the line (Reproduced)

- [ ] **Where:** `backend/latex/applicator.py:92`
- **Cause:** `replacement_text` is inserted without escaping LaTeX special characters.
- **Example:** `Reduced cycle time by 40% in R and D cells.` compiles without error, and the
  PDF reads `Reduced cycle time by 40`. The rest of that source line is lost too.
- **Fix:** escape unescaped `%`, `&`, `#` and `_`. Leave `\%` and `\&` as they are, and
  respect math and commands already present in the original span. Confirm `&` separately:
  it has meaning inside tables.
- **Test:** plain and already-escaped `%`, plus a compile test that reads the PDF text.

### 3. Letter text is used as a regex template (Reproduced)

- [ ] **Where:** `backend/latex/injector.py:50-51`
- **Cause:** the paragraph is part of the `re.subn` replacement string.
- **Example:** `\textbf{keen}` becomes a TAB followed by `extbf{keen}`; `\emph{keen}` raises
  `bad escape \e`. The "keep the original paragraph" path is affected too, because
  `inject_letter_edit` is called outside the `try` in `backend/latex/pipeline.py`.
- **Fix:** use a function replacement: `lambda m: m.group(1) + new_content + m.group(2)`.
- **Test:** `\textbf`, `\emph`, `\textbackslash{}` and `\%` pass through unchanged.

## Sunday: applying and review

### 4. Queue keyboard shortcuts use the wrong route (Read in code)

- [ ] **Where:** `frontend/src/routes/queue/+page.svelte:341`,
  `frontend/src/lib/components/CVReviewPanel.svelte:59`
- **Cause:** both register on `/`, but `+layout.svelte` passes `$page.route.id`, which is
  `/queue`, and the dispatcher needs an exact match.
- **Fix:** register both on `/queue` and update the comments. First check in the browser
  whether `CVReviewPanel` is used on another route.
- **Test:** j, k, a, m, s and Enter work on the queue; the review keys work in the panel.

### 5. The employer's application link is lost (Read in code)

- [ ] **Where:** `backend/monitor/store.py:112` and `:134`
- **Cause:** insert stores `apply_url or url`, so the later upgrade, which needs an empty
  `apply_url`, almost never runs. If LinkedIn or Indeed is seen first, the direct ATS link
  found later is discarded.
- **Fix:** replace an aggregator link with a known ATS link; never the reverse.
- **Test:** LinkedIn then Greenhouse keeps Greenhouse; Greenhouse then LinkedIn also does.

### 6. A submit click that never happened counts as "maybe sent" (Read in code)

- [ ] **Where:** `backend/applier/harness/runner.py:269,286-287`
- **Cause:** `act` raises `StalePage` before clicking, but `_submit` turns every exception
  into `needs_verification`.
- **Effect:** an unsent application can be locked and use daily quota.
- **Fix:** treat only the pre-click `StalePage` as "not sent" and return to review.
  **Any error during or after the click must stay `needs_verification`**, so nothing is
  ever submitted twice.
- **Test:** one test for each side of the click.

### 7. Fields inside scrolling containers may be missed (Inferred)

- [ ] **Where:** `backend/applier/harness/snapshot.js:169,180`;
  `scroll_for_more` in `backend/applier/harness/agent.py`
- **Cause:** scrolling is offered only when the document itself scrolls. Nested scroll
  containers are not considered.
- **Effect:** a form in a modal or inner panel could be called complete too early.
- **First:** build a fixture with a required field below an inner fold and confirm it fails.
- **Fix:** report the nested scroller and its centre; send the wheel event there.

### 8. Gmail sync position is never saved on the first run (Read in code; known as R01)

- [ ] **Where:** `backend/gmail/sync.py:138`, `_update_cursor` at `:215`
- **Cause:** `historyId` is read from the `messages.list` response, which does not carry it,
  so `_update_cursor` receives `None` and returns.
- **Fix:** take `historyId` from `users.getProfile` before listing, so mail arriving during
  the backfill is not skipped.
- **Test:** use a `messages.list` fake without `historyId`.

### 9. French rejection emails are not recognised (Read in code; known as R12)

- [ ] **Where:** `backend/gmail/classifier_heuristics.py:37`
- **Cause:** rejection patterns are English only.
- **Fix:** add, for example, `n'a pas été retenue`, `nous avons le regret` and
  `ne donnerons pas suite`, with straight and curly apostrophes.
- **Test:** French rejections match; French acknowledgements do not.
